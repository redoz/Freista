Modern top-down activity diagram — how should objects appear?

Real top-down UML activity diagram: initial node → actions → fork/join → final, Given/When/Then as stacked swimlanes, modern styling (soft rounded action cards, smooth thick connectors, the GWT palette, lots of whitespace). Control flow is the spine. The only thing that differs between the two is how objects and their flow are drawn. Click whichever reads cleaner — or tell me in the terminal.

1 · Inline object nodes (objects ride the flow)

Objects are colored chips sitting on the control edge between the action that produces them and the one that consumes them — and the edge itself takes the object's color while that object is the token in transit. Grey = pure control (start, fork/join sync bars, end). Compact, and you read an object's journey straight down the spine.

2 · Object side-rail (control spine stays pure)

The vertical spine is only control flow; every object lives as a card in a right-hand rail, with dashed colored connectors arcing from the producing action to the card and on to the consumer. Keeps the control flow dead simple, and scales when a step touches many objects — at the cost of more crossing connectors.
